# 评测方法

需要验证提示词效果、比较模型或分析失败案例时使用。先明确本轮要验证的变化，再按任务选择检查项。

## 核对案例与评分口径

优化效果前，先把案例预期核对到最终渲染的输入和用户目标，检查摘要、标签是否冲突，以及来源和时间是否足以支持预期判断。把接口、截断、格式失败与语义错误分开，再区分目标改善、遗留错误与新增错误；原文语义诊断不能替代实际可用结果的成绩。输入没有提供的时序或纠错知识不能暗作通过条件。

调整评分口径时保留旧分、注明版本，并用同一口径重评对照；重复场景还要按场景汇总，不能当作独立证据累加。

## 受控对照

每轮实验先写清可检验的假设与改变的因素，再做单变量配对：改提示词时固定案例、模型和其他内容；比较模型时先对齐业务所需的速度档位、思考开关、输出预算与并发，并核对实际请求参数。快档与最高思考档的结果不能直接用于模型选型；不同厂商同名思考档也不代表相同预算。

把“信息出现”“状态正确”“相关输出一致”按任务需要分别检查，隐藏版本名判读后再汇总。

## 归因与下一轮

只把对照支持的变化归因于该改动：组合有效不证明每项有效，文本改写不等于任务解决，少量输赢不当作稳定收益。先分析残留错误，再决定下一项最小实验，不因失败不断追加规则。

报告哪些改善、哪些未改善，以及原因中哪些已验证、哪些仍是假设；具体领域策略留在业务提示词中。
