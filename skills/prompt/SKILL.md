# Prompt

先读当前提示词、输入输出约定与已有的相近样例，理解本轮目标和用户认可的表达方式。依据当前任务选择以下阶段，保留已有契约与有效内容。

## 判断阶段

| 阶段 | 适用情形 | 本轮工作 |
| --- | --- | --- |
| 初始化 | 新任务，或核心需求尚未明确 | 确认任务类型、目标、必要输入、核心判断与输出，写出满足核心需求的最小可用初稿。 |
| 定向优化 | 已有提示词，有明确的修改目标或失败案例 | 先判断问题来自表达、业务逻辑、上下文还是模型表现，再调整相关部分。缺少资料、历史状态或工具能力时，先处理相应依赖。 |
| 验证与沉淀 | 需要确认效果、比较方案或交付版本 | 按改动范围检查语义与实际结果，记录有效变化和残留问题。开展效果评测前阅读[评测方法](references/evaluation.md)。 |

按本轮目标判断阶段，允许回退。仅整理表达时，核对语义和契约即可；实际效果改善需要对应样例验证，不自动扩展为整套模型评测。

## 按任务选择 ICTIO

Instruction 承载目标与执行逻辑；Context 提供背景、历史和已有数据；Tools 说明工具能力与调用规范；Input 定义入参；Output 约定出参结构与表达要求。按需选择 Block，已有运行时契约明确的内容无需在提示词中重复抄写。

| 任务类型 | 常用组合 | 需要时补充 |
| --- | --- | --- |
| 参数提取、意图分类 | Instruction + Input + Output | Context 提供候选集合、历史或领域资料。 |
| 文本生成、角色表达 | Instruction + Output | Context 提供素材、用户偏好和风格样例。 |
| 检索问答 | Instruction + Context + Output | 主动检索时加入 Tools；查询有严格格式时加入 Input。 |
| 工具执行、多轮服务 | Instruction + Tools + Output | Context 提供已有参数与状态；Input 定义结构化请求。 |
| 复杂判断 | Instruction + Context + Output | Input 定义需要严格校验的材料格式。 |

以上组合是起点，具体取决于任务依赖。变量用占位符传入；具体业务策略、工具名和字段约定由当前任务提供。

初始化时先理清核心规则，再决定如何表达。一个 goal 能完整承载时就保留一句，例如：

> 从对话中提取用户明确承诺且尚未完成的待办。

需要先后判断或条件分流时再展开 workflow；rules 补充流程未覆盖的约束与例外；examples 示范判断或表达。每项要求放在最合适的位置，不为章节完整补写内容。

## 提炼可执行指令

1. 从原话提取希望改变的行为，明确模型要识别、比较、选择、调用或输出什么。将“充分理解、灵活处理、确保准确”等抽象期待落实到具体决策；缺少关键判据时补清业务含义，不借润色擅自创造策略。
2. 按判断的依赖顺序组织动作，在真正分流的位置使用“若……则……”“仅当……时……”“否则……”。只展开影响结果的关键节点，明确依据与优先级，保留处理新情况的空间。
3. 用准确动词和明确对象替换铺垫、隐喻与含混指代，保留必要条件和完整语法。精炼以语义完整、快速理解为准，满足任务明确的长度约束，不以生硬缩写或凑字数代替内容取舍。
4. 通读各句，保留独立增加目标、依据、动作、条件、优先级或边界的内容，合并重复要求。Instruction 中的启发式描述应落实为执行要求；Context 中的事实和 Output 中的字段说明按各自职责表达。

例如，业务已明确“唯一订单直接查询，多笔订单需要区分”，就可把“充分理解用户需求，结合上下文灵活处理，必要时追问，确保查询准确”提炼为：

> 根据当前请求与已有信息定位订单：唯一匹配时查询；匹配多个时，只追问用于区分订单的信息。

用判断策略指导表达，只有业务要求固定文案时才写死句子。列举情况时区分完整范围与典型示例；任务允许无结果、无需行动或依据不足时，明确对应出口。

## 组织上下文与表达

让核心目标容易在开头识别，长材料集中分区，当前任务与输出要求靠近结尾；按输入长度和实际模型调整布局。位置影响关注程度，不能代替证据决定事实优先级。补齐必要资料、合并重复信息，同时保留来源、时间与不确定状态，避免把资料缺失当作否定事实。

用自然连贯的语言连接目标、适用情境与行为边界；解释原因只在有助于模型判断时加入。提示词自身示范期望的清晰文风，具体输出语气由任务决定。优先保留用户已认可的示例，确需修改时针对具体问题；示例只承担声明的示范用途，不把示例事实当作当前输入，也不把偶然措辞变成固定模板。

交付时说明关键改动与验证范围。需要扩展文风、示例或长上下文设计时，按需查阅下列材料，不将特定模型的建议直接当作跨模型保证。
